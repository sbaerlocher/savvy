# Technology Stack

## Architecture

Single Go binary serving a JSON API plus an embedded SvelteKit SPA. The
backend follows a strict three-layer pattern; the frontend is an
offline-first PWA that talks only to `/api/v1/*`.

```
SvelteKit SPA  ──HTTPS──▶  Echo (Go) JSON API  ──▶  Services  ──▶  Repositories  ──▶  GORM / PostgreSQL
                                                           ▲
                                                           └── Workers/goroutines (reminders, session cleanup)
```

- Frontend assets are built with Vite, copied into `internal/assets/client/`,
  and served by the Go binary via `//go:embed`.
- All cross-cutting concerns (auth, CSRF, sessions, rate limit, i18n, OTel)
  live as Echo middleware in `internal/middleware/`.

## Core Technologies

- **Backend language**: Go 1.26+
- **HTTP framework**: Echo v5 (`labstack/echo/v5`)
- **ORM**: GORM with PostgreSQL driver
- **Migrations**: Embedded Gormigrate (`go-gormigrate/gormigrate/v2`); no
  separate SQL files
- **Frontend**: SvelteKit 2.x + Svelte 5 + TypeScript, Vite 7, Tailwind CSS 4
- **Adapter**: `@sveltejs/adapter-static` (SPA mode, `fallback: index.html`)
- **PWA**: `@vite-pwa/sveltekit` with custom service worker
  (`injectManifest` strategy) using Workbox recipes (`NetworkFirst` +
  `warmStrategyCache`)
- **Database**: PostgreSQL 16

## Key Libraries (only those that shape patterns)

- **Auth/Session**: `gorilla/sessions` with a custom PostgreSQL-backed
  `PGStore` (SHA-256-hashed tokens, IP/UA tracking).
- **OAuth/OIDC**: `coreos/go-oidc/v3` + `golang.org/x/oauth2` (provider-agnostic).
- **2FA**: `pquerna/otp` for TOTP; secrets AES-256-GCM encrypted, backup
  codes bcrypt-hashed.
- **Web Push**: `SherClockHolmes/webpush-go` with VAPID.
- **Validation**: `go-playground/validator/v10` at handler/DTO boundary.
- **i18n**: `nicksnyder/go-i18n/v2` (backend) + a TS i18n module (frontend);
  always wire DE/EN/FR.
- **Observability**: OpenTelemetry SDK + OTLP HTTP exporters,
  `prometheus/client_golang` for `/metrics`, `slog` for structured logs.
- **Frontend barcode**: `barcode-detector` polyfill (browser scan), `bwip-js`
  (server-side rendering).

## Development Standards

### Type Safety

- Go: services and repositories are **interface-first**; concrete
  implementations live in `*_impl.go` siblings. All new business logic must
  expose an interface so it can be mocked.
- TypeScript: SvelteKit project runs in strict mode via `svelte-check`;
  prefer real types over `any`.

### Code Quality

- Go: `golangci-lint` (config in `.golangci.yml`), `revive` (`.revive.toml`).
- Frontend: Prettier + `prettier-plugin-svelte`, `svelte-check` for type
  errors.
- YAML/Markdown: `yamllint`, `markdownlint`.
- Secrets: `gitleaks` runs in CI; never commit `.env`, secrets, or
  credentials.
- Pre-commit / EditorConfig enforced; conventional commits with the
  Co-Authored-By trailer required (see global commit-message skill).

### Testing

- Backend: `go test ./...` with `-race`. Repositories test against real
  PostgreSQL (not mocks); services use mocked repos. Mocks live under
  `internal/mocks/` and are generated by Mockery (`.mockery.yaml`).
- Frontend: Playwright E2E suite under `client/tests/e2e/`. Tests run
  against a real Docker stack started by `client/tests/global.setup.ts`;
  there is no project dependency graph beyond globalSetup/globalTeardown.

### Logging

- Use `slog` with structured fields. Do **not** introduce new `log.Println`
  call sites; that migration is finished.

## Development Environment

### Required Tools

- Docker + Docker Compose (the only supported way to run dev).
- Go 1.26+ for editor tooling and `go test`.
- Node.js (version pinned in `.nvmrc`) for `client/` scripts.

### Common Commands

```bash
# Run the full dev stack (Vite + Air-reloaded Go API + Postgres)
docker compose up

# Build production binary with embedded SvelteKit assets
cd client && npm run build:embed
make build   # or: go build ./cmd/server

# Backend tests with race detector
go test ./... -race

# Frontend tests
cd client && npm run test:e2e:run -- tests/e2e/<file>.spec.ts
```

### Critical Dev Rule

**Never start frontend or backend dev servers on the host.** Vite's proxy
target is `http://api:8080`, which only resolves inside the Compose network.
`npm run dev`, `air`, etc. on the host will produce confusing proxy errors.
Edit files locally; Air and Vite hot-reload inside containers.

## Key Technical Decisions

- **Layered architecture, interface-first**: handlers never touch GORM
  directly; services never touch `echo.Context`. Authorization is centralized
  in `AuthzService` and called from every protected handler.
- **Server-side sessions, not JWT**: `PGStore` keeps the cookie opaque,
  enables revocation, "log out other devices", and stale-session
  invalidation tied to `users.password_changed_at`.
- **UUIDs over integer IDs** for all user-facing resources.
- **Database triggers for invariants** that would be expensive in app code
  (e.g. `recalculate_gift_card_balance`, `enforce_lowercase_email`).
- **Polymorphic favorites** (`resource_type` + `resource_id`) instead of one
  pivot table per resource.
- **Embedded migrations** (Gormigrate in Go) so the binary is self-contained
  and `AUTO_MIGRATE=true` works in any environment.
- **Feature toggles via env vars** (`ENABLE_*`) with both server-side
  middleware and a `/api/v1/config` endpoint the client reads at startup.
- **PWA: NetworkFirst + warmup cache, IndexedDB for mutations**. Cache
  validation on `online` event removes resources the user lost access to
  while offline.
